# 功能說明與介接規格

## 功能範圍

F1-A 對應每日健康追蹤項目設定與紀錄寫入。可見流程草稿包含：依 route 分流、設定列寫入 TrackingSettings、每日紀錄 append 至 DailyRecords，以及預留的前日資料查詢、差異提醒、RecordAlerts 寫入與 LINE OA 推播分支。

本次不將後三項描述為已完成；資料比較節點仍標示「待接線」，且未驗收端到端通知。

## Sheets 工作表

請看 `GoogleSheets_schema.csv`。六張工作表：Families、Members、MetricDefinitions、TrackingSettings、DailyRecords、RecordAlerts。欄位名稱以目前表頭及流程 JSON 為依據；CSV 不含任何資料列或識別值。

## 流程呼叫介面（依 JSON 節點推讀，部署前需核對）

Webhook 為 POST，路徑在目前 JSON 不可見（此 F1 JSON 無 Webhook Trigger 節點，不能據此提供部署 URL）。流程預期上游驗證節點提供已驗證 payload，至少含 `route`、`familyId`、`lineUid`；設定寫入另使用 `metricKey`、`enabled`、項目欄位及門檻值；紀錄寫入使用 `recordId`、`recordedAt`、`recordDate`、`period`、`metricKey`、`value`、`unit` 等欄位。

流程回傳 JSON 形狀預期為 `{ ok, familyId, role, metrics, settings }`（設定）或 `{ ok, savedCount, recordedAt, recordDate, period, warnings }`（紀錄）。實際入口／完整欄位契約需與 LIFF 來源及上游身份驗證模組對照；LIFF 原始碼本次未取得。

## 組員接手前置

1. 找回並確認 LIFF 實際部署網址、程式碼版本與呼叫 payload。
2. 匯入 JSON 後設定目標環境 Sheets OAuth、LINE OA 憑證；不要複製其他 n8n 實例的 credential IDs。
3. 確認身份驗證/授權節點與管理者/一般成員權限。此 JSON 本身沒有 Webhook Trigger、沒有身份驗證節點，不能獨立視為可部署工作流。
4. 修正並驗證前日同人、同指標、同時段查詢；明確處理同日重複紀錄與跨日邊界。
5. 完成 RecordAlerts 去重、通知成功/失敗狀態與 LINE 測試帳號驗收，再更新狀態。
